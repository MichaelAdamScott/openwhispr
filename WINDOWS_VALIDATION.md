# Windows validation

Validated October 26, 2026, on Windows x64 (build 26200), using Node.js 24.x.
The implementation starts from upstream commit
`6408cd9a1081dc4935706fcbba6aaeae1d2cd18d` (OpenWhispr 1.10.4).

## Actual native inference

The smoke test used the production `registerCustomLocalSpeechIpc` helper,
registry, `WhisperManager`, and `ParakeetManager`, with the native binaries from
the app's pinned runtime versions. The Electron app shell and native selection
dialog were simulated to choose known local files. Model validation, managed
copies, native loading, transcription, registry listing, switching between
engines, and removal all used the real implementation.

| Imported model                                                              | Native runtime                             | Import including load check | Transcription | Transport                               |
| --------------------------------------------------------------------------- | ------------------------------------------ | --------------------------- | ------------- | --------------------------------------- |
| whisper.cpp tiny.en GGML, 77.7 MB                                           | OpenWhispr whisper.cpp 0.0.11, Windows CPU | 308 ms                      | 295 ms        | Bound to `127.0.0.1`                    |
| Third-party Underdog Bark 3.0 int8 ONNX, about 685 MB including attribution | sherpa-onnx 1.13.8, Windows CPU            | 2,097 ms                    | 1,989 ms      | Command-line process, no listening port |

These timings are single smoke runs, not performance benchmarks. Input was a
7.4-second, 16 kHz mono PCM16 WAV generated by Windows speech synthesis:

> The quick brown fox jumps over the lazy dog. This is a local speech recognition test for custom models.

Both engines returned all expected words, compared after normalizing case and
punctuation. The imported Bark conversion automatically used `pad_s=0.25` from
its encoder metadata, with no extra user manifest. Its output omitted case and
punctuation in this sample.

The tests also switched Whisper → Bark → Whisper, confirmed the other native
engine stopped, removed the managed imports through IPC, confirmed original
source files remained, and ended with an empty managed test cache and both
engines stopped. Separate helper smoke runs also passed.

The tested ONNX files came from
[velddev/Underdog-Bark-3.0-sherpa-onnx](https://huggingface.co/velddev/Underdog-Bark-3.0-sherpa-onnx).

## Automated and visual checks

200 targeted automated tests passed (55 UI/regression and 145 backend/locale),
with one macOS-only test skipped on Windows. This was the affected test set,
not a run of every test in the repository.

- UI regression tests cover persisted selection, importing both formats, loading
  status, cancellation, errors, deletion, provider switching, onboarding
  readiness, duplicate filtering, and exclusion from live meeting streaming.
- Backend tests cover format validation, unsupported Bark/MLX/Core ML files,
  ONNX external-data rejection, malformed tokens and manifests, safe IDs,
  copying and rollback, runtime argument handling, padding, cancellation, and
  Windows handle cleanup before removal.
- Existing affected tests cover stock Parakeet, WAV normalization, segmentation,
  Whisper's local request fields, model-cache migration, and sherpa packaging.
- Renderer production build, TypeScript, translation parity, and ESLint passed.
  ESLint reports existing warnings outside the changed functionality.
- An actual offscreen Electron window rendered the new component with example
  imported rows; its captured layout was visually inspected.

## Limits of this validation

This is a source implementation. A full Windows installer was not built, and
manual native-dialog clicking, live microphone capture, global hotkeys, and
end-to-end text insertion into another application were not exercised. macOS
and Linux native inference were not tested.

The original Underdog `.bark` package remains unsupported by this importer;
using it directly needs the separate official Python/PyTorch runtime. This
validation establishes compatibility of the tested ONNX conversion only. It
does not establish the original publisher's accuracy claims, compatibility of
all future conversions, arbitrary ONNX architectures, GPU acceleration for
custom ONNX, or live streaming support. ONNX models reload for each decode.
